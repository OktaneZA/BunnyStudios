## Architecture assessment

The existing modular monolith fits the current deployment: React/Vite, Fastify, Postgres,
local object storage and an in-process durable runner. The pure compiler and generated model
registry are real packages, not placeholders. No new backend architecture is required for
the accepted UI simplification.

Useful boundaries already present:

- `useSceneText` serialises saves, retains a session draft and exposes recovery/readiness.
- The server compiles scene instructions, validates references and calculates quotes.
- Creative snapshots pin inputs and lineage independently of later character edits.
- Account locking couples job creation to allowance reservation; claim fencing protects
  terminal job updates. Ambiguous submitted work retains an unknown estimated charge.
- Character pictures remain candidates until approval. The first allowed scene video may
  auto-fill an empty slot; later videos do not replace a selected clip automatically.

Limitations are explicit: one in-process runner deployment is the established shape; multiple
instances have not been certified. Mixed video/audio references and native provider draft
completion are not exposed. Catalogue presence and fake-provider tests do not establish live
access, quality or billing. `verified_live` is metadata; rollout gates and configuration still
determine availability, including the explicit `VIDEO_FAMILY_ROLLOUT=all` override.
