# Codebase, security and architecture review — 2 October 2026

Scope: the whole repository on `feature/video-optimisation` after the video optimisation
stages 0–4 (`2c4b5e9`) and the pre-paid pot (`d51855c`). Three independent read-only passes
(security, architecture, code quality) over `apps/api`, `apps/web`, `packages/*`, the
Dockerfile, the Synology deployment and CI; every finding below was then checked against the
code by hand. Nothing was run against a live provider. This is a point-in-time review, not a
penetration test or a live-provider certification.

**Headline:** no critical finding. Account isolation, the child-safety gates and the money
path are done carefully and consistently. The real gaps were at the edges: one runner window
that could resubmit a paid request, the first-day arithmetic of the new pot, sign-in with no
brute-force protection, and a handful of reads that forgot `deleted_at`. The items marked
**fixed** were corrected in the same branch (commit after this document); the rest are ranked
for follow-up.

## 1. Fixed in this pass

| Area | Finding | Fix |
|---|---|---|
| Runner / money | A shutdown while a request was in flight set `submission_state = 'uncertain'`, handed the job back, and the next pickup only guarded `'submitting'`: the same clip could be sent to fal twice ([runner.ts](../apps/api/src/jobs/runner.ts)). | The pickup guard now treats `uncertain` like `submitting`: the job fails as "unknown cost", no resubmission, no refund. Test: *a shutdown while the request is in flight never sends it again*. |
| Money | `refund()` accepted `settled` rows, so any future caller could turn a real bill into "not incurred" and refill the pot. | Refund only ever undoes a `reserved` row. Test: *a refund never undoes a settled bill*. |
| Money | Migration 0013 seeded the pot with one month's budget, but the pot counts spending from all time, so an account with earlier months' spending woke up short. | Migration 0015 adds, once, a correction equal to spending before this month. The pot after it equals what the monthly cap would have allowed today. |
| Money | The boundary "pot exactly equal to the price" was untested. | Tested: it is enough. |
| Production | "Make another version" of a clip made before recipes existed re-asked with `use_latest` and no length, so the child saw "Choose how long the clip should be" on a screen with no length control. | Length and sound fall back to the parent clip's. |
| Production | A recipe whose maker had left the catalogue was re-routed to any maker without picture tokens, sending `@Image1` text to a words-only model. | 422 "That clip's maker is not available any more", with `can_use_latest`. |
| Production | A final re-routed to a sibling maker could dead-end on a size the sibling lacks. | The base size is kept only when the maker has it; otherwise the maker's default. |
| Production / web | Making the first clip of an unsaved cast saved it and bumped the shot version, but the response did not say so; the next frame or look edit got a spurious 409. | The 202 carries the fresh shot; the screen takes it, and the two edits that did not re-read on 409 now do. |
| Compiler | Two characters with the same name were merged: one description, all pictures. | `CompileCharacter.id` (optional); dedupe and token matching by id when given, by name otherwise. Test added. |
| Security | No rate limit on `POST /auth/login`; anyone on the LAN could guess passwords at scrypt speed. | Ten *wrong* attempts a minute per address lock sign-in for a minute (429). Successful sign-ins never count, so a household signing in and out is never locked out. In memory, no dependency. Test added. |
| Security | The timing-equalising dummy hash (`scrypt$00$00`) failed before scrypt ran, so an unknown email answered in <1 ms and a known one in ~60 ms. | A real scrypt hash of a random password is computed at start-up and used as the dummy. |
| Security | `GET /assets/:id/file` and `GET /me` ignored `deleted_at`; a binned picture stayed downloadable and a binned account kept passing `/me`. | Both filter it. The file route also sends `X-Content-Type-Options: nosniff` and `Content-Disposition: inline`. |
| Security | `POST /characters/:id/restore` presented rejected pictures and the reviewer's reason to the teen. | It now hides them for a minor like every other character route. |
| Operability | `runner.tick().catch(() => {})` in four routes swallowed the only error at the moment the user is waiting. | Logged through the request logger. |
| Runner / money | Reserved money had no reaper: a `queued` job nobody picked up (runner off, provider renamed, container gone) held its reservation for ever. | `runner.sweep()`, once a minute: a job still waiting after `GENERATION_QUEUE_TIMEOUT_MS` (default 2 h) with nothing sent to the provider is stopped ("That took too long to start, so it was stopped. Nothing was spent.") and refunded. Runs for every provider on purpose. The adult gets "Stop this job" in the clip log and may stop anyone's job. Test added. |
| Architecture | Three route files hand-wrote the same job-creation ritual, and Director Mode's `POST /shots/:id/jobs` still sent the *still* prompt to clip makers. | `jobs/create.ts` `createJob()` owns lock → idempotency → insert → reserve → tick for all three. Video on `POST /shots/:id/jobs` is retired (422); clips go through `POST /shots/:id/videos` only, which the web already used. `ownCharacter` reads inside the transaction. |
| Wording | "Generation isn't connected yet. Ask the account owner", "No provider credits are used", and "picture maker" on a clip error. | "Picture making isn't switched on yet. Ask a grown-up.", "Nothing is spent.", and clip/picture by kind. `ProblemBox` now logs the hidden error to the console. |

## 2. Open findings, ranked

### Security

| Priority | Finding | Recommendation |
|---|---|---|
| P1 | The NAS serves `http://192.168.1.73:3001`: the bearer token and every picture cross the LAN in clear, and tokens live 30 days in `localStorage` with no revocation (a password change does not log anyone out). | Put the app behind DSM's HTTPS reverse proxy (the Synology README already describes it) and set `CORS_ORIGINS` to match. Shorten tokens to 7 days and add a `token_version` on the account checked in `requireAuth`. |
| P2 | No security headers: no CSP, no `frame-ancestors`, no `Referrer-Policy`. Uploads are magic-byte checked and there is no `innerHTML` in the web app, so there is no known XSS, but with the token in `localStorage` a CSP is the only backstop. | `@fastify/helmet` with a CSP that allows `blob:` for images and video. |
| P2 | `generation/fal.ts` downloads whatever result URL fal returns, with no scheme or host check. A tampered response could make the NAS fetch internal addresses. | Require `https:` and allow only fal's media hosts; reject private ranges. |
| P3 | Video safety review for the teen samples two frames per part (start and middle). Content between samples is unreviewed. Fail-closed behaviour is right. | Sample on a fixed cadence (every 2 s, capped) for constrained accounts. Document the limitation until then. |
| P3 | fal 4xx bodies are logged with up to 600 characters of `detail`, which can echo a child's scene text; `seed.ts` logs account emails at every boot. | Log field names and error types only; log account ids, not emails. |
| P3 | `scene_thumbnail` assets are the one hard delete in the API ([thumbnails.ts](../apps/api/src/routes/thumbnails.ts)). | Set `deleted_at` like everything else. |
| P3 | `strictSafety` on the provider request is set and never read: `safety_tolerance` is a static default, so the adult gets the teen's setting and the teen nothing stricter. D32 gate 2 is therefore a per-catalogue setting, not per account. | Make `request_shape.safety` a `{field, strict, standard}` triple and branch on it, or delete the flag and the gate-2 wording from the docs. |
| P3 | Raw `ARRAY[...]` literals in `shots/sync.ts` and `runner.ts` are built by string interpolation. Safe today (uuid columns and `randomUUID()`), fragile tomorrow. | Bind the array as a parameter (`= ANY(${ids}::uuid[])`). |
| P3 | Free-text scene and project fields have no length limits beyond the 1 MB body cap; multipart accepts 25 MB before `validateUpload` rejects at 10/20 MB; `trustProxy: true` in production trusts any `X-Forwarded-For` (which matters now that login is rate limited by address). | Add `max()` to the zod schemas; align the multipart limit; set `trustProxy` to the proxy's address. |

Checked and found sound: every route loads by `(id, account_id)` and answers 404, never 403;
`request.accountId` only comes from the verified JWT; adult-only routes 404 for a minor; rejected
assets are hidden from the minor in every presenter and the render; generation refuses for a
constrained account when the reviewer is off, at creation and at run time; keys only ever go in
request headers and upstream bodies are never reflected into user errors; AI output is strictly
schema-validated and lands as proposals; uploads are magic-byte checked with metadata stripped,
no SVG or HTML accepted, storage keys server-generated and validated; ffmpeg runs via `execFile`;
no `.env` has ever been committed; the container runs as `node` with a data-only DB role.

## 3. Done well, and not to be changed

- The pure compiler, vocabulary-derived enums and server-only compilation; the frozen
  `CreativeVideoSnapshot` as the recipe of every clip.
- The runner's core: claim with a fence on every write, heartbeat, durable `next_poll_at`,
  `submission_state` written before the call, part resume, review gates that fail closed, and
  money changed only by whoever ended the job. The resubmission gap was one missing branch.
- Money as a derived number under the account row lock, `quoteGeneration` as the single price
  function with a provenance snapshot, and `quote_key` = hash(recipe + pricing) checked under
  the same lock with an idempotency key.
- `account_id` everywhere with 404-not-403, soft delete with `sceneIsLive`/`projectIsLive`,
  `If-Match` with `current_state` on 409.
- Looks as immutable revisions pinned by content hash, with ordered manifests that refuse
  rather than truncate.
- The catalogue checked offline against a committed snapshot of fal's own schemas, which has
  already caught a wrong field.
- `useSceneText`: serial autosave with a draft in session storage, explicit conflict state and
  a hard `settle()` before anything is spent.
